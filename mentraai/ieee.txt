TITLE:
Mentra.ai: An AI-Powered Meeting Assistant Platform with Real-Time Voice Interaction and Intelligent Summarization

ABSTRACT:
This paper presents Mentra.ai, a comprehensive meeting management platform that integrates artificial intelligence to enhance virtual collaboration through real-time voice interaction and intelligent summarization. The system leverages OpenAI's GPT-4o Realtime API for natural voice conversations, Whisper-1 for speech-to-text transcription, and Google's Gemini 2.5 Flash for automated meeting summarization. Built on a modern web architecture using Next.js, Stream Video SDK for video conferencing, and Inngest for background job processing, Mentra.ai provides users with customizable AI agents that can participate in meetings, transcribe discussions, and generate structured summaries. The platform addresses key challenges in remote collaboration by providing context-aware AI assistants that can be tailored for specific meeting types such as sales calls, technical reviews, and team meetings. This paper discusses the system architecture, technical implementation, and evaluation of the platform's effectiveness in improving meeting productivity and information retention.

KEYWORDS:
AI Meeting Assistant, Real-time Voice Processing, Video Conferencing, Natural Language Processing, Meeting Summarization, WebRTC, Stream Video SDK, OpenAI Realtime API

================================================================================
1. INTRODUCTION
================================================================================

The rapid shift to remote work has transformed how organizations conduct meetings, with video conferencing becoming the primary mode of collaboration. However, traditional video conferencing platforms often lack intelligent features that can enhance meeting productivity, information retention, and post-meeting follow-up. Participants frequently struggle with note-taking, action item tracking, and comprehensive documentation of discussions.

Recent advances in artificial intelligence, particularly in natural language processing and real-time voice interaction, present opportunities to address these challenges. AI-powered meeting assistants can participate in conversations, transcribe discussions in real-time, and generate structured summaries that capture key decisions, action items, and important insights.

This paper introduces Mentra.ai, a novel meeting management platform that integrates AI agents directly into video calls. The system allows users to create customizable AI agents with specific personalities and instructions tailored to different meeting contexts. These agents can participate in discussions using natural voice interaction, transcribe conversations using advanced speech recognition, and automatically generate comprehensive meeting summaries using state-of-the-art language models.

The key contributions of this work include:

1. Integration of OpenAI's GPT-4o Realtime API with Stream Video SDK for seamless voice interaction in video calls
2. A flexible agent configuration system that allows users to define AI behavior through natural language instructions
3. Automated meeting summarization pipeline using Google's Gemini 2.5 Flash model
4. Background job processing architecture using Inngest for scalable meeting analysis
5. A modern web application architecture built on Next.js with end-to-end type safety using tRPC

The remainder of this paper is organized as follows: Section 2 discusses related work in AI meeting assistants and real-time voice processing. Section 3 presents the system architecture and technical implementation. Section 4 describes the agent configuration and customization system. Section 5 details the meeting processing pipeline. Section 6 discusses the implementation details and technology stack. Section 7 presents evaluation and results. Section 8 concludes with future work directions.

2. RELATED WORK
================================================================================

2.1 AI Meeting Assistants

Recent years have seen significant development in AI-powered meeting assistants. Otter.ai and Fireflies.ai provide automated transcription and meeting intelligence features, but primarily focus on post-meeting analysis rather than real-time participation. Microsoft Teams Copilot and Zoom AI Companion offer in-meeting assistance but with limited customization options for agent behavior.

Research in this area has explored various approaches to meeting intelligence, including automatic speech recognition (ASR), speaker diarization, and meeting summarization. However, most existing solutions treat AI as an external observer rather than an active participant in the conversation.

2.2 Real-Time Voice Processing

The emergence of real-time voice processing APIs has enabled new possibilities for human-AI interaction. OpenAI's Realtime API provides low-latency voice-to-voice communication, allowing for natural conversations with AI assistants. This represents a significant advancement over traditional text-based chat interfaces and voice command systems.

WebRTC (Web Real-Time Communication) has become the standard for peer-to-peer audio and video communication in web applications. Stream Video SDK builds on WebRTC infrastructure to provide scalable video conferencing with advanced features like selective forwarding units (SFU) and adaptive bitrate streaming.

2.3 Meeting Summarization

Meeting summarization has been an active area of research in natural language processing. Traditional approaches used extractive summarization techniques, while more recent work has explored abstrive summarization using transformer-based models. The integration of large language models (LLMs) has significantly improved the quality of generated summaries, enabling better capture of context, nuance, and action items.

2.4 Background Job Processing

Scalable web applications require efficient background job processing for tasks that are not time-critical. Inngest provides a modern approach to workflow orchestration with event-driven processing, step execution, and automatic retry logic. This is particularly important for meeting processing, which may involve computationally intensive tasks like transcription analysis and summarization.

3. SYSTEM ARCHITECTURE
================================================================================

3.1 Overview

Mentra.ai follows a modern web application architecture with a clear separation of concerns. The system consists of the following main components:

- Frontend: Next.js application with React and TypeScript
- Backend: API routes using Next.js App Router
- Database: PostgreSQL with Drizzle ORM
- Video Infrastructure: Stream Video SDK
- AI Processing: OpenAI Realtime API and Google Gemini
- Background Processing: Inngest workflow engine
- API Layer: tRPC for type-safe client-server communication

3.2 Frontend Architecture

The frontend is built using Next.js 15 with the App Router, providing server-side rendering and optimized performance. React 19 is used for the user interface with TypeScript for type safety. Tailwind CSS provides utility-first styling with a custom dark violet theme.

The application is organized into feature modules including:
- Dashboard module for main navigation
- Agents module for AI agent management
- Meetings module for meeting scheduling and management
- Calendar module for visual calendar interface
- Call module for video conferencing interface

3.3 Backend Architecture

The backend leverages Next.js API routes for server-side logic. Better Auth handles authentication with support for email/password and OAuth providers (Google, GitHub). Session management uses HTTP-only cookies for security.

tRPC provides end-to-end type safety between client and server, eliminating runtime type errors and improving developer experience. TanStack Query manages server state with automatic caching and background refetching.

3.4 Database Architecture

PostgreSQL serves as the primary database, hosted on Neon for serverless scaling. Drizzle ORM provides type-safe database queries with automatic schema migrations. The database schema includes tables for users, sessions, accounts, agents, and meetings with appropriate relationships and constraints.

3.5 Video Infrastructure

Stream Video SDK provides the video conferencing infrastructure, building on WebRTC for peer-to-peer audio/video streaming. The system uses a Selective Forwarding Unit (SFU) for media routing and bandwidth management. Webhooks from Stream Video trigger server-side events for meeting lifecycle management.

3.6 AI Processing Pipeline

The AI processing pipeline consists of two main components:

1. Real-time Voice Processing: OpenAI's GPT-4o Realtime API handles voice-to-voice interaction during calls, with Whisper-1 for speech-to-text transcription and Server VAD for voice activity detection.

2. Meeting Summarization: Google's Gemini 2.5 Flash processes meeting transcripts to generate structured summaries with executive summaries, key decisions, action items, and next steps.

3.7 Background Processing

Inngest handles background job processing for meeting analysis. When a meeting ends, the system triggers an asynchronous workflow that fetches the transcript, processes it with AI, and updates the database with the summary. This ensures that the main application remains responsive even during computationally intensive tasks.

4. AGENT CONFIGURATION AND CUSTOMIZATION
================================================================================

4.1 Agent Model

Agents are represented in the database with the following schema:
- id: Unique identifier (nanoid)
- name: Display name for the agent
- instructions: AI system prompt defining behavior
- userId: Owner of the agent
- createdAt: Creation timestamp
- updatedAt: Last update timestamp

4.2 Instruction Enhancement

When users create an agent, they provide basic instructions describing the agent's purpose and behavior. The system enhances these instructions using Google's Gemini 2.5 Flash model to create comprehensive, professional system prompts. The enhancement process includes:

1. Defining the agent's role and purpose clearly
2. Specifying personality and communication style
3. Outlining key responsibilities and capabilities
4. Including guidelines for interaction and behavior
5. Setting boundaries and limitations

This enhancement ensures that agents have well-defined behavior while allowing users to provide simple, natural language descriptions.

4.3 Agent Types

The system supports various agent types for different meeting contexts:

- Sales Agent: Optimized for sales calls, lead qualification, and product demonstrations
- Support Agent: Handles customer service, troubleshooting, and FAQs
- Meeting Assistant: Takes notes, summarizes discussions, and tracks action items
- Technical Specialist: Provides technical expertise and code review
- HR Assistant: Handles employee onboarding and policy questions

Each agent type can be further customized through the instruction system to match specific organizational needs.

4.4 Agent Participation in Calls

When a meeting starts, the system automatically connects the assigned agent to the call using Stream Video's OpenAI integration. The agent joins as a participant with:

- Agent User ID: The agent's unique identifier
- System Instructions: The enhanced prompt from the database
- Voice Configuration: Selected voice type (alloy, echo, fable, etc.)
- Turn Detection: Server-side voice activity detection for natural conversation flow
- Transcription: Whisper-1 model for speech-to-text conversion

The agent listens to participant audio, processes it through OpenAI's Realtime API, and responds with natural voice output, creating a seamless conversational experience.

================================================================================
5. MEETING PROCESSING PIPELINE
================================================================================

5.1 Meeting Lifecycle

The meeting lifecycle consists of the following stages:

1. Scheduling: User creates a meeting with selected agent and scheduled time
2. Initiation: User joins the call, triggering session start webhook
3. Agent Connection: System connects agent to the call with configured instructions
4. Active Phase: Agent participates in conversation with real-time voice interaction
5. Termination: User leaves the call, triggering session end webhook
6. Transcription: Stream Video generates transcript in JSONL format
7. Processing: Inngest workflow processes transcript with AI
8. Summarization: Gemini generates structured summary
9. Completion: Database updated with summary and transcript URL

5.2 Webhook Integration

Stream Video webhooks drive the meeting lifecycle:

- call.session_started: Triggers agent connection and marks meeting as active
- call.session_ended: Triggers agent cleanup and marks meeting as processing
- call.transcription_ready: Provides transcript URL for processing
- call.recording_ready: Provides recording URL for storage

Webhook signatures are verified using Stream Video SDK to ensure security and authenticity.

5.3 Transcript Processing

The transcript processing pipeline handles JSONL format transcripts from Stream Video:

1. Fetch: Retrieve transcript from provided URL
2. Parse: Parse JSONL format line by line
3. Speaker Identification: Map speaker IDs to user and agent names from database
4. Context Enrichment: Add speaker information to transcript items
5. AI Processing: Send enriched transcript to Gemini for summarization

Error handling includes access permission checks, format validation, and retry logic for network issues.

5.4 AI Summarization

The summarization process uses Google's Gemini 2.5 Flash model with a specialized system prompt that instructs the AI to generate structured summaries including:

- Executive Summary: 2-3 sentences capturing primary purpose and outcomes
- Key Decisions Made: Bullet points of concrete decisions reached
- Action Items: Specific tasks assigned with responsible parties
- Important Discussion Points: Major topics covered and insights shared
- Next Steps: Follow-up actions and future meeting requirements

The system prompt emphasizes accuracy, completeness, clarity, relevance, and professional presentation suitable for executive review.

5.5 Background Job Orchestration

Inngest manages the background processing workflow:

1. Event Trigger: Webhook sends "meetings/processing" event
2. Step Execution: Sequential processing steps with state persistence
3. Error Handling: Automatic retry with exponential backoff
4. State Management: Track processing progress and completion
5. Database Update: Final step updates meeting record with summary

This architecture ensures reliability and scalability, allowing the system to handle multiple concurrent meeting processing tasks.

6. IMPLEMENTATION DETAILS
================================================================================

6.1 Technology Stack

Frontend:
- Next.js 15.3.2: React framework with App Router
- React 19: UI library with concurrent features
- TypeScript 5: Type-safe JavaScript development
- Tailwind CSS 4: Utility-first CSS framework
- Radix UI: Accessible component library
- Lucide React: Icon library

Backend:
- Next.js API Routes: Server-side logic
- Better Auth 1.2.8: Authentication library
- PostgreSQL: Primary database
- Drizzle ORM 0.44.4: Type-safe database queries
- tRPC 11.1.2: Type-safe API layer
- TanStack Query 5.76.1: Server state management

Video & AI:
- Stream Video SDK 1.19.7: Video conferencing
- OpenAI Realtime API: GPT-4o for voice processing
- Whisper-1: Speech-to-text transcription
- Google Gemini 2.5 Flash: Meeting summarization
- Inngest 3.40.2: Background job processing

6.2 Authentication System

Better Auth provides comprehensive authentication with:
- Email/password authentication
- OAuth 2.0 integration (Google, GitHub)
- Session management with HTTP-only cookies
- CSRF protection
- Secure token generation and validation

The authentication system is configured with a base URL to support development environments using ngrok for webhook testing.

6.3 Database Schema

The database schema is designed for relational integrity and scalability:

User Management:
- user: User accounts with authentication data
- session: User sessions for authentication
- account: OAuth provider accounts
- verification: Email verification tokens

Application Data:
- agents: AI agent configurations
- meetings: Meeting records with status tracking

Relationships:
- Users → Sessions (one-to-many)
- Users → Accounts (one-to-many)
- Users → Agents (one-to-many)
- Users → Meetings (one-to-many)
- Agents → Meetings (one-to-many)

6.4 API Design

tRPC provides type-safe API procedures organized by feature:

Agents Router:
- create: Create new agent with instruction enhancement
- getMany: List agents with pagination and search
- getOne: Get single agent details
- update: Update agent with optional instruction regeneration
- remove: Delete agent
- previewEnhancedInstructions: Preview AI-enhanced instructions

Meetings Router:
- create: Create new meeting
- getMany: List meetings with filters and pagination
- getOne: Get single meeting details
- update: Update meeting information
- remove: Delete meeting
- generateToken: Generate Stream Video authentication token

6.5 Video Call Implementation

The video call interface consists of several components:

Call Lobby: Pre-call setup with device testing and permission requests
Call Connect: Stream Video client initialization with error handling
Call Active: Active call interface with controls and speaker layout
Call Ended: Post-call summary and navigation

The system handles device permission errors gracefully, allowing users to join calls without microphone devices and providing clear error messages.

6.6 Error Handling

Comprehensive error handling is implemented throughout the system:

- Device permission errors with fallback options
- WebSocket connection failure handling
- API error responses with user-friendly messages
- Database transaction error handling
- Webhook signature verification failures
- Background job retry logic with exponential backoff

6.7 Performance Optimization

Several optimization techniques are employed:

- Next.js server-side rendering for improved initial load
- React Query caching and deduplication
- Code splitting with dynamic imports
- Image optimization with Next.js Image component
- Database query optimization with proper indexing
- Connection pooling via Neon serverless PostgreSQL
- Adaptive streaming for video calls

8. CONCLUSION AND FUTURE WORK

8.1 Conclusion

Mentra.ai represents a significant advancement in AI-powered meeting assistance, integrating real-time voice interaction, intelligent summarization, and customizable AI agents into a unified platform. The system addresses key challenges in remote collaboration by providing context-aware AI assistants that can participate naturally in conversations while automatically generating comprehensive meeting documentation.

The technical architecture leverages modern web technologies and AI services to create a scalable, performant, and user-friendly solution. The use of tRPC for type safety, Inngest for background processing, and Stream Video for video conferencing demonstrates effective integration of specialized services to create a cohesive system.

Preliminary evaluation shows positive results in terms of system performance, user experience, and agent effectiveness. The platform successfully demonstrates the potential of AI to enhance meeting productivity and information retention.
